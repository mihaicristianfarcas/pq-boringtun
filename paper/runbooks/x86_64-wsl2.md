# x86_64 measurement runbook (Windows + WSL2 Ubuntu)

This runs the same Criterion benches and the memory probe on x86_64 Linux,
to neutralise the "is this ARM-specific?" review objection. Target host:
the user's Windows PC, with an Ubuntu 22.04/24.04 WSL2 instance.

Roughly 20 minutes end-to-end once the toolchain is installed.

## 0. One-time setup

In an admin PowerShell:

```powershell
wsl --install -d Ubuntu
```

If WSL2 + Ubuntu is already present, skip. Open the Ubuntu shell and run the
rest from there.

### Toolchain

```bash
sudo apt-get update
sudo apt-get install -y build-essential pkg-config git curl
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y
. "$HOME/.cargo/env"
rustup default stable
rustc -vV | grep host  # expect: host: x86_64-unknown-linux-gnu
```

## 1. Clone the repo on the `paper` branch

```bash
cd ~
git clone https://github.com/<you>/pq-boringtun.git    # or fetch your own remote
cd pq-boringtun
git checkout paper
```

## 2. Disable the sudo cargo runner

The repo's `.cargo/config.toml` sets `runner = 'sudo -E'` for `cfg(unix)`
because the macOS test target needs elevated privileges for a TUN device.
On WSL2 we have no TUN setup and the benches need none — drop it for this
run by setting an env runner:

```bash
export CARGO_TARGET_X86_64_UNKNOWN_LINUX_GNU_RUNNER="env"
```

Do **not** commit this change to `.cargo/config.toml`; the env var keeps the
override local.

## 3. Run the crypto bench (both feature modes)

```bash
# Vanilla
cargo bench --bench crypto_benches 2>&1 | tee paper/measurements/x86_64-crypto-vanilla.txt

# Hybrid (includes ML-KEM-512/768/1024)
cargo bench --bench crypto_benches --features pq 2>&1 | tee paper/measurements/x86_64-crypto-pq.txt
```

Expected duration: ≈ 4 min per pass. Criterion writes a `target/criterion/`
report tree; the tee'd text file is what we need for the paper.

## 4. Run the handshake bench (both feature modes)

```bash
# Vanilla (randomises vanilla vs psk_slot order per iter to kill warm-up bias)
cargo bench --bench handshake_benches 2>&1 | tee paper/measurements/x86_64-handshake-vanilla.txt

# Hybrid
cargo bench --bench handshake_benches --features pq 2>&1 | tee paper/measurements/x86_64-handshake-pq.txt
```

## 5. Run the memory probe

```bash
cargo run --release --example memory_probe 2>&1 | tee paper/measurements/x86_64-memory-vanilla.txt
cargo run --release --example memory_probe --features pq 2>&1 | tee paper/measurements/x86_64-memory-pq.txt
```

## 6. Paste back

Each `paper/measurements/x86_64-*.txt` is the raw bench output we need. The
two memory-probe outputs are short — paste them inline in the chat. For the
Criterion text logs, only the per-benchmark `time: [low mid high]` lines
matter; you can `grep -E "^[a-z0-9_/]+ +time:" paper/measurements/x86_64-*.txt`
to get a compact summary.

## 7. (Optional) Validate the build inside the loopback handshake test

```bash
cargo test --release --features pq noise::tests 2>&1 | tail -20
```

A green test confirms the hybrid handshake completes on x86_64 Linux end-to-end
in addition to the bench harness — a useful side-check that the implementation
is not silently ARM-specific.

## Reference: CPU and platform notes

When pasting numbers, also report:

```bash
lscpu | grep -E "Model name|Flags" | head -2
cat /etc/os-release | grep PRETTY_NAME
uname -a
```

— particularly whether the CPU exposes AVX2/AVX-512 (relevant for the
x25519-dalek benchmark; portable backend on x86_64 vs the NEON path on ARM
is exactly the kind of thing reviewers ask about).
